# 010. Python as the parity proof; the Rust tooling removed

Date: 2026-11-16
Status: Accepted (the maintainer's decision, 2026-11-16). Amends ADR 006.

## Context

ADR 006's method ran the frozen Rust crate (`rust-old/`, with its hidden `oracle` hooks) through a Rust generator,
`scripts/golden/` (5,886 lines), to write the golden corpus, and timed Rust twins, `scripts/probes/rust/` (1,671
lines), beside the Cyrius benches. The corpus was committed: `tests/golden/` held 100 MB, `dist.tsv` alone 52 MB, past
GitHub's recommended file size, and every part's regeneration stored a new copy (`.git` reached 212 MB).

The port exists to leave Rust, and the tooling made the project more dependent on it. Rust's run was also no longer
the proof: `validate.py` already re-derived every row in Python, 1.3.0's own bits through glibc (ctypes) and the
correctly rounded and T1 values through MPFR.

## Decision

- **The corpus is generated by Python.** `scripts/golden/gen.py` and its emitters in `scripts/golden/emit/`, one per
  module, port the Rust emitters' grids; every output comes from `validate.py`'s models. On 2026-11-16 the Python
  corpus equalled the Rust-made one on all 329,431 rows in fn, class, inputs and outputs (NaN payloads aside, which
  class A ignores), and the replay gave the same result: 275,753 rows ok and 53,678 accepted.
- **The corpus is never committed.** `tests/golden/` is in `.gitignore`. CI writes it (`gen.py`, then
  `validate.py --write-cr`) before `cyrius test`; locally the same two commands, about 3 minutes. Its digests are
  committed instead (`scripts/golden/digests.txt`, one sha256 per file): `gen.py --digests` fails on a machine whose
  libm gives other bits than the recording one (glibc 2.44, x86_64, FMA), and `gen.py` refuses another machine or a
  CPU without FMA outright.
- **Accuracy beats glibc, as before.** The base rows keep 1.3.0's own bits (the glibc model), which ADR 009's "no row
  less accurate than Rust" rule measures against. The port is gated against the correctly rounded and T1 overlays
  (`*.cr.tsv`, `*.ref.tsv`), from MPFR.
- **New modules are proved the same way.** From M4 on, each module's Python model is transcribed from
  `rust-old/src`, and MPFR (or exact arithmetic, or NIST StRD) supplies the references. `rust-old/` stays as source
  text until M8e. Nothing runs it.
- **Removed:** `scripts/golden`'s Rust crate; `scripts/probes/rust/` (the bench and probe twins) and the probes that
  needed them (P0, P1, P5, P7 and P9's drivers); `scripts/port-baseline/` (the Rust 1.3.0 accuracy baseline), but for
  its MPFR checker `check.c` and `merge.py` (C and Python), which moved to `scripts/crverify/`; and CI's `rust-oracle`
  job. `validate.py` reads the T1 lnΓ coefficients from `src/lgamma_data.cyr`, not the cargo registry.
- **Benchmarks:** the Rust numbers already in `docs/benchmarks-rust-v-cyrius.md` stay as recorded. From M4 the Rust
  column is 1.3.0's criterion record (`rust-old/benchmarks.md`, 2026-11-14, this host), and each Cyrius bench does
  its criterion bench's work, measured pinned as before.

## Consequences

- **Positive:** no Rust toolchain is needed to build, test or regenerate anything. The repository no longer grows by
  a corpus copy per part. One language, Python, holds the proof, and it was shown equal to the Rust run on every row.
- **Negative:** from M4 on, Rust's execution no longer checks the Python models. The Python transcription and the
  Cyrius port are two independent readings of the same source, and agreement at 0 ulp is the proof. A misreading
  shared by both would pass. 1.3.0's own unit tests, carried into each module's Cyrius tests, and the MPFR and NIST
  references guard against that.
- **Unchanged:** the 212 MB already in history stays unless the history is rewritten, which is the maintainer's call.

## Alternatives considered

- **Keep the Rust generator, untrack only the corpus.** Rejected by the maintainer: it keeps the project dependent on
  the language it is leaving.
- **Commit the inputs only, outputs computed at test time.** Still tens of MB of data in git.
- **Git LFS for the corpus.** Moves the bytes, keeps the Rust dependency.
